## 已修：导出备份后首页提醒不刷新（我 8-31 引入的小 bug）
- 现象：在首页点备份卡片上的「⬇ 现在导出备份」后，`ytLastBackup` 已写入，但卡片仍显示"💾 还没备份过"，必须手动刷新页面才变成"备份正常"。
- 原因：exportAll 只写 localStorage 并 toast，没有触发首页重渲染。
- 修复：exportAll 末尾加 `if (location.hash === '#/home' || location.hash === '') route();`（仅在首页时重渲染，避免在其他模块导出时无谓刷新/关抽屉）。
- 位置：app.js 约 3999-4001 行。

## 新发现：两处功能重叠（做加法留下的后遗症，比继续加模块更该先解决）

### 重叠 1：选题存哪？两套并存
- `💡 选题灵感`(ideas)：上半＝系统每日自动推荐的选题（读 data/daily-ideas.json，离线走本地题库兜底）；下半＝「➕ 我的灵感（收藏/手动添加）」，存在 `ideas` 仓库。
- `📝 公众号助手`(gzh)：自带**选题池**（状态流水线 想写→草稿→已发布，可设预计发布日），存在 `gzh` 仓库。
- → 玉婷自己想到的选题，两边都能存，互相看不到，必然困惑该记哪。

### 重叠 2：日常打卡记哪？两套并存
- `📋 每日计划`(daily)：有 routine 标签的"每日必做"（健身操/尤克里里/英语），存在 `tasks` 仓库，按 date 取当天。
- `🔥 我的习惯墙`(habits)：连续天数打卡，存在 `habits` 仓库。
- → 同一件"每天健身操"既可以放每日计划也可以放习惯墙，两边数据不通。

# 实施记录（玉婷回复「① ②」后动手）

## ① 选题入口合并（renderIdeas 改造）
数据结构对齐：
- ideas 仓库（选题灵感·我的灵感）：`{ text, auto, collected, potential, tag, desc, createdAt, id }`
- gzh 仓库（公众号助手·选题池）：`{ kind:'idea', title, pillar, planDate, note, status:'idea'|'draft'|'done', created, id }`

改造内容：
1. view.innerHTML 的「➕ 我的灵感（收藏/手动添加）」区 → 改成「📋 我的选题」：说明文案 + 「➕ 加个选题」+「📝 去选题池」两个按钮。
2. 新增 `moveToPool(it)`：ideas → gzh 选题（`text→title`，`desc + 【爆款潜力】+【标签】→ note`，`status:'idea'`，`created: createdAt`）。
3. `renderMine()` 重写：ideas 为空则整块隐藏；非空则顶部显示橙色虚线「📦 这里有 N 条旧灵感」卡片 + 「全部搬到选题池」按钮（confirmDel 二次确认，**搬完原数据保留**，用户可自行删）；每条旧灵感卡片加「→ 搬到选题池」单条按钮。
4. `#manual` 改为直接写 gzh（字段简化为 选题 + 备注），toast「已存进公众号选题池 📋」。
5. `#goPool` → `go('gzh')`。

→ 效果：新选题只有公众号选题池一个入口；旧数据一键搬家且不丢。

## ② 首页「今天该做什么」（renderHome）
- view.innerHTML 新增 `<div id="todayBox">` 容器（在 backupTip 之后、quoteCard 之前）。
- 新增 `paintToday()`：聚合三件事 —— `DB.byDate('tasks', today)` 未完成数→跳 daily；`DB.all('habits')` 今天未打卡数→跳 habits；`DB.get('gratitude', today)` 未写→跳 gratitude。每行一个跳转按钮。
- 三项都空时显示「✅ 今天该做的都做完了」鼓励语。
- 调用位置：`paintBackupTip()` 之后 `await paintToday()`。
