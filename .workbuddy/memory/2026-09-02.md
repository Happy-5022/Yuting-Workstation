# 2026-09-02 清理 .git 遗留（昨晚 filter-branch 的收尾）

## 发现：本地 .git 反而涨到 153M（重建前才 81M）
- 昨晚 filter-branch + gc 后，远程干净了（HEAD d32df74），但**本地 .git 仍是 153M**。
- 原因：`git filter-branch` 会创建 **`refs/original/` 备份引用**，指向重写前的旧 commit 链。只要这些引用在，`git gc` 就无法回收旧对象——**包括那个 5.3M 的 wav 完整副本**。
- 所以昨晚的清理只干净了远程，**本地还留着一份完整旧历史**。

## 处理（已完成）
```
git update-ref -d refs/original/refs/heads/main
git update-ref -d refs/original/refs/remotes/origin/main
git update-ref -d refs/original/refs/stash
git reflog expire --expire=now --all
git gc --prune=now
```
- ⚠️ Windows Git Bash 里 `xargs` 报 `environment is too large for exec`，改用逐条 `git update-ref -d` 才成功。

## 结果
- **`.git`：153M → 36M**
- 历史完好：`8332680 每日选题更新 2026-09-02` / `d32df74 瘦身...` / `cb84b69 移除隐私音频...`
- **`git log --all -- voice-clone/` 返回空** → wav 已不在任何历史里
- pack 内最大对象：8.8M（ppt-project 的 IP动画分镜脚本_2x3.png，非隐私）、1.5M/1.3M（quotes 背景图）→ **无 5.3M 音频 blob，确认清除**
- 网站 HTTP 200，远程同步（`## main...origin/main`）

## 意外好消息
- **「每日自动更新选题」自动化任务正常**：今早自动提交了 `8332680 每日选题更新 2026-09-02`，说明仓库重建后自动化没断（之前担心过）。

## 遗留
- .git 剩 36M，其中约 8.8M 是 ppt-project 分镜图的历史 blob（非隐私，是玉婷创作素材的历史，可留作找回用，暂不清理）。
- 若要进一步瘦到 ~14M，需再跑一次 filter-branch 清 ppt-project 历史（但会丢素材找回能力，不推荐）。

## 教训（写给自己）
- ⚠️ **`git filter-branch` 之后必须手动删 `refs/original/`**，否则 gc 无效，本地历史体积不降反升（旧对象+新对象并存）。
- ⚠️ 验证"历史是否真清干净"要用 `git log --all -- <path>` 和 `git verify-pack` 查最大 blob，不能只看 `du -sh .git`。
- ⚠️ Windows Git Bash 的 `xargs` 容易因环境变量过大失败，优先用 for 循环或逐条命令。
