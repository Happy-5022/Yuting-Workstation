## 越南语新词发音「词音错位」bug 修复（11:12）
- 现象：用户跑 gen_vn_audio.py 生成并 push 后，反馈越南语模块"有些词和音对不上"（点词听到别的词的发音）。
- 根因：`scripts/gen_vn_audio.py` 的 `_load_topic_words()` 用正则 `vn: '...'` 从 vn-data.js 提取词，但每个主题词都带例句 `ex: { vn: '...' }`，**例句 vn 被一并抓取并按顺序编号 NX_**；而网页 `VN_AUDIO_MAP` 自动遍历只认主题词 `w.vn`、不认 ex.vn。两边 NX_ 序号错位 → 文件内容对不上词。
- 修复：① `_load_topic_words()` 先 `re.sub(r"ex:\s*\{[^}]*\}", "ex:{}", _src)` 剔除例句块再提取，并去重（模拟网页"同一 vn 只分配一个 NX_"）；② `main()` 生成前用 glob 删除 AUDIO_DIR 下所有 NX_*.mp3，防止旧错位文件残留。
- 发布关键：重跑后必须 `git add -A`（非 `git add .`），否则 GitHub 上旧的错位 NX_ 文件不被删、网页仍加载错误发音。已在 `scripts/越南语音频生成说明.md` 第三步强调。
- 待办：用户在电脑重跑 `python scripts/gen_vn_audio.py` → `git add -A` → commit → push；手机划掉 PWA 重开验证。

## 越南语词音错位·第二轮修复——`_load_covered_texts()` 元组 bug（11:44）
- 现象：用户按上一轮修复重跑脚本并 push 成功（截图确认 `main -> main`），但试听仍存在"词和音对不上"。
- 根因（更深一层）：`_load_covered_texts()` 第171行 `re.findall(r"m\['([^']*)'\]\s*=\s*'([^']*)'", _src)` 返回的是**元组列表** `[('Cảm ơn', 'NW_001'), ...]`，而第203行 `_vn not in _covered` 用**纯字符串**去查**元组集合**——字符串永远不等于元组 → **所有词都被判"未覆盖"→ 全部重新编号**。
- 结果偏差：网页端跳过113个已有映射的旧词，新词从 NX_001 编起；脚本端一个没跳过，384个词全从 NX_001 编到 NX_384。**两边差了整整113个位置**，每个新词都听到错位发音。
- 修复：`return set(re.findall(...))` → `return set(m[0] for m in re.findall(...))`，只取第一个捕获组（越南语文字本身），使 _covered 为纯字符串集合，与网页端 `!m[w.vn]` 行为一致。
- 待办：用户需再次在电脑重跑脚本 + git add -A + push；手机划掉 PWA 重开验证。
- **【已解决·12:01】用户重跑并 push 后试听，确认越南语新词发音与词完全对应、无错位。越南语音频词音对齐问题到此彻底关闭。**
