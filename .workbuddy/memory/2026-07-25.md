## 重大根因复盘：越南语发音"不对"的真凶（用户 19:52 点破）

## 越南语点开空白：根因是 Service Worker 缓存旧 app.js（21:20 排查）
- 现象：代码静态看全对（语法 OK、DB.get('meta',..)/put 签名对、VN_* 常量都在、paintHome 逻辑通），但预览点开越南语模块空白。
- 真凶：`sw.js` 对 js/css 等静态资源用**缓存优先(caches.match 先返回)** + 缓存名写死 `yt-wb-v1`。用户多轮改代码期间，SW 早已把"删掉越南语那版"的 app.js 缓存住，之后永远吐旧缓存 → 越南语入口可能还在(中间版本)但 renderViet 不渲染 → 空白；其他模块旧版功能没变故看似正常。
- 修复：① `sw.js` 改为 **network-first**（先联网取最新，失败才用缓存）+ 升版本号 `yt-wb-v2` + install 时 addAll 失败不阻塞；② `index.html` 的 `app.js` 引用加 `?v=2`（cache-busting，绕过普通 http 缓存）。双保险确保刷新即拿最新。
- 经验：**PWA 在频繁改代码阶段，SW 绝不能"缓存优先静态资源+固定版本号"**，否则改了等于没改。要么 network-first，要么每次改完升 CACHE 版本号。
