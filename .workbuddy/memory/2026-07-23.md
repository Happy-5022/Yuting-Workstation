  1. `getVoicePref('vi-VN')` 残留了一个**英语嗓音名**的脏记忆（错语言！不是"难听越南语嗓音"）。`speakLang` 里 `VOICES.find(x=>x.name===pref)` 在设备 voice 列表里找到了这个**英语 voice**（它确实存在，只是 lang=en-US），于是 `u.voice=英语voice` → iOS 用英语嗓音逐字母读越南语拉丁文本 → "像读英文字母"。
  2. 为什么清不掉：`renderVoicePicker` 在越南语 `list`（按 lang 过滤后的 vi 语音）为空时**直接 `return`**，跳过了清除逻辑、也不渲染"恢复默认"按钮 → 用户"看不到越南语下拉"，脏记忆永久残留。
- **根治（js/app.js）**：
  1. `speakLang` 加**语言校验**：仅当 pref 指向的 voice 的 lang base 等于目标 lang base 才绑定；否则视为脏记忆→`setVoicePref(lang,'')` 清除并**只用 `u.lang`** 让系统自动选母语嗓音（核心防呆，杜绝任何"用错语言嗓音"）。
  2. `renderVoicePicker`：**移除 `list` 为空时的提前 return**，改为始终渲染下拉（至少"自动（推荐）"）+「↺ 恢复默认」按钮，且**先执行脏记忆清除**再渲染 → 越南语模块永远有"恢复默认"入口。
  3. `renderViet` 开头 `setVoicePref('vi-VN','')` **进模块即清脏记忆**，朗读立刻恢复系统越南语发音。
  4. 移除 `speakVi` 里的 `warnVoiceOnce`（iPhone 上会误报"朗读不准"误导用户）。
  5. `paintViStatus`/`vietTipCheck` 文案改温和（不再强求下载语音包，因 `u.lang='vi-VN'` 在 iPhone 能读对）；告警色 `.warn-note` 换新增 `.info-note`（蓝灰温和，css/style.css 已加）。
  6. `doSpeak` 加 `synth.resume()` 与 `try/catch` 包裹 `synth.speak`，提升 iOS 稳定、缓解"点了没声音"。
- node 语法校验通过（Bash 本次恢复，返回"语法OK"）。**预期效果**：推完硬刷新进越南语模块，所有喇叭（字母/声调/单词/场景/课文）均用 iPhone 自带标准越南语发音，不再逐字母、不再静默。
- ⚠️ 固化经验：TTS 朗读的"发音人记忆"必须**按目标语言校验**，绝不能因 pref 在 VOICES 里存在就绑定（它可能属于另一语言）。voice 对象一旦绑定，其 lang 会覆盖 utterance.lang，是跨语言误读的根因。
